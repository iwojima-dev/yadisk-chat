# YaDisk Chat

> P2P-мессенджер с E2E-шифрованием поверх Яндекс.Диска. Один Python-файл. Никаких зависимостей. Никакого сервера.

## Как это работает

Каждый участник хранит историю переписки в своём **Яндекс.Диске**. Сообщения записываются в `JSONL`-файлы, к которым собеседник получает доступ через публичную ссылку. Никакого промежуточного сервера — только Яндекс.Диск как транспорт.

```
Алиса                              Боб
  │  disk:/YaChatV2/contacts/       │  disk:/YaChatV2/contacts/
  │    └─ contact-XYZ/              │    └─ contact-ABC/
  │         inbox.jsonl  ◄──────────┤         inbox.jsonl  ◄──────
  │         attachments/ (pub)      │         attachments/ (pub)
  └──────────────────────────────────┘
           публичные ссылки (read-only)
```

Ни одно сообщение не проходит через сторонний сервер. Приложение запускается локально и общается с API Яндекс.Диска напрямую.

## Возможности

- Текстовые сообщения — мгновенная отправка, автообновление (~5 с поллинг)
- E2E-шифрование — AES-256-GCM + PBKDF2-SHA-256 (120 000 итераций); шифрование происходит в браузере, сервер не имеет доступа к ключу
- Изображения — отправка, inline-превью, скачивание через встроенный прокси
- Файлы любого типа — отправка и скачивание
- Несколько контактов — переключение в один клик, счётчик непрочитанных
- Тёмная / светлая тема — автоопределение системных настроек, ручное переключение
- Звуковое уведомление о новом сообщении (Web Audio API, без внешних файлов)
- Авто-восстановление контактов и истории при перезапуске из структуры папок на диске

## Быстрый старт

### 1. Создайте OAuth-приложение Яндекса

1. Зайдите на [oauth.yandex.ru](https://oauth.yandex.ru) → **Создать приложение**
2. Тип: **Веб-сервис**
3. Права доступа: `cloud_api:disk.read` + `cloud_api:disk.write`
4. Callback URI: `http://127.0.0.1:8765/auth/callback`
5. Сохраните **ClientID**

### 2. Запустите сервер

```bash
python server.py
```

Приложение откроется в браузере по адресу **http://127.0.0.1:8765**

### 3. Авторизуйтесь

В боковой панели введите **ClientID** и имя пользователя → нажмите **Войти через Яндекс**.  
Альтернативно: вставьте токен вручную через кнопку «вручную».

### 4. Настройте диск

Нажмите кнопку **Настроить диск** — на Яндекс.Диске создастся структура папок `disk:/YaChatV2/`.

### 5. Добавьте контакт

1. Нажмите **+ Добавить контакт** — появится ваша публичная ссылка
2. Передайте её собеседнику любым способом (один раз)
3. Вставьте ссылку собеседника → **Добавить**

## Структура данных на диске

```
disk:/YaChatV2/
└─ contacts/
   └─ contact-{id}/
      ├─ inbox.jsonl        ← ваши исходящие сообщения (публичный, read-only)
      └─ attachments/
         └─ {rand}.{ext}    ← вложения (публичные)
```

Каждая строка `inbox.jsonl` — отдельный JSON-объект:

```jsonc
// Незашифрованное сообщение
{"id":"msg-abc123","kind":"text","from":"alice","ts":1700000000000,
 "payload":{"enc_stub":"plain","text":"Привет!"}}

// Зашифрованное сообщение (AES-256-GCM)
{"id":"msg-def456","kind":"text","from":"alice","ts":1700000001000,
 "payload":{"v":1,"alg":"AES-GCM","iv":"<base64>","ct":"<base64>"}}

// Файл или изображение
{"id":"msg-ghi789","kind":"image","from":"alice","ts":1700000002000,
 "name":"photo.jpg","size":204800,"path":"disk:/YaChatV2/contacts/.../photo.jpg"}
```

## Шифрование

Шифрование **опционально** и настраивается отдельно для каждого контакта (кнопка с замком в шапке чата).

| Параметр | Значение |
|---|---|
| Алгоритм | AES-256-GCM |
| Деривация ключа | PBKDF2-SHA-256, 120 000 итераций |
| Соль | `YaChatV2-e2e-v1` (фиксированная) |
| IV | 12 байт, случайный для каждого сообщения |
| Где происходит | Только в браузере (Web Crypto API) |
| Что видит сервер | Зашифрованный blob — расшифровать невозможно |
| Хранение ключа | Только в памяти вкладки, не сохраняется |

> Оба участника должны использовать **одинаковый пароль**. Передайте его по защищённому каналу.

## Ограничения

- Не real-time: новые сообщения появляются через ~5 секунд (поллинг)
- Нет системных push-уведомлений (только звук в браузере)
- История хранится у отправителя; удаление файла уничтожит её
- OAuth-токен хранится в памяти — при перезапуске нужна повторная авторизация
